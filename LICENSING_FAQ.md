# MycEvo Licensing FAQ — Approval Draft

## Is MycEvo open source?

No OSI claim is made. The intended model is **source-available**: source code can be inspected and the approved license will define permitted use.

## Is the current candidate already the repository license?

No. `LICENSE.CANDIDATE.md` is held behind the G1 owner/legal gate. Until an approved `LICENSE.md` exists, default copyright rules apply.

## Can an individual use and modify MycEvo locally?

That is an intended permitted use under the license candidate, subject to final approval.

## Can a company use MycEvo for its own internal workflows?

That is also an intended permitted use under the license candidate, subject to final approval.

## Can a consultant help a client deploy MycEvo internally?

This fact pattern must be checked against the final license and the parties' roles. The FAQ does not create permission beyond the approved license. Ask for written clarification before relying on this scenario commercially.

## Can someone run a paid hosted MycEvo service or sell a white-label copy?

The intended boundary requires a separate commercial license for direct paid hosting, multi-tenant resale or white-label sale of MycEvo itself.

## Can someone independently build a product inspired by the same idea?

The software license governs the covered code and other protected material, not the abstract idea of an external workflow brain. MycEvo's durable advantage must come from execution, brand, integrations, evidence contracts and ecosystem.

## Are export, deletion and security updates paid features?

The product boundary keeps user-data export/deletion, local provenance, human promotion authority, security fixes and published-format compatibility outside the Team paywall.

## Does this FAQ override the license?

No. If this FAQ conflicts with an approved `LICENSE.md`, the approved license controls.
